# TTRI 交付內容說明

> 給非工程背景的同事看的版本。日期：2026-08-10

## 一句話總結

客戶給的是「一本說明書 + 一箱素材」。素材我已經全部搬進系統可以用了；說明書裡講的兩支連線功能，程式我寫好了，但因為缺帳號和網址，現在還連不出去。

---

## 1. 客戶給了什麼

資料夾 `TTRI to VJINC` 裡有四包東西，772 MB：

| 這包是什麼 | 白話解釋 |
|---|---|
| **兩份 API 說明書**（Excel） | 教我們怎麼跟紡織所的伺服器要資料 |
| **資料內容.xlsx** | 網頁上那些下拉選單要放什麼選項（布種、組織、成分、顏色…） |
| **Asset 檔案** | 3D 模型、背景、布樣照片、圖案圖檔 |
| **Pattern 生成 API 資料** | AI 生圖功能的規格與範例 |

## 2. 我做了什麼

### (1) 把 Excel 變成程式看得懂的選單

客戶的選項全放在 Excel 裡。我寫了一支轉檔程式，跑一次就自動把 Excel 變成網頁用的資料檔。

好處是：**之後客戶更新 Excel，我們重跑一次就好，不用手動一筆一筆改**，也不會抄錯。

轉出來的東西：

- 布種 4 種、組織 13 種、成分 41 種、彈性 4 種
- 布重、布厚的合理範圍（使用者亂填會被擋下來）
- 40 筆布樣的完整資料
- 24 個 3D 模型、3 種背景、15 張圖案

### (2) 把素材整理成網頁載得動的大小

客戶給的原始檔太大了 —— 單一張布料貼圖就 47 MB，網頁根本載不動。

我做了自動壓縮：**725 MB → 266 MB**，畫質肉眼看不出差別。一樣是寫成腳本，客戶補新素材時重跑就好。

### (3) 把畫面接上真資料

原本的畫面是用假資料做的示意圖，現在換成客戶的真東西：

| 原本 | 現在 |
|---|---|
| 搜尋結果永遠是寫死的兩張卡 | 真的去比對 40 筆布樣，依布種、組織、成分排出相符的 |
| 布料卡顯示 CSS 畫的假花紋 | 顯示客戶給的真實布樣照片，有 3D 檔的會標上「U3M」 |
| 內建圖案是 6 個色塊 | 15 張客戶提供的真圖案 |
| 3D 預覽是一顆程式畫的球 | 真的載入客戶的 24 個模型（沙發、外套、鞋子…）和 HDR 背景 |
| 布重布厚可以亂填 | 超出範圍會擋下來並提示 |

## 3. 現在能跑到什麼程度

**可以跑的**：開啟系統 → 填規格 → 搜到真實布樣 → 選圖案 → 3D 預覽 → 下載 u3m 檔。

**還不能跑的**：任何需要連到紡織所伺服器的功能。

---

## 4. 卡在哪裡

客戶的 API 有一個限制：**帳號會綁定一個固定的 IP 位址**。

意思是紡織所只認得「某一台特定電腦」。但使用者是從自己家裡、公司各種不同的網路連進我們的網站，IP 每個人都不一樣，所以**瀏覽器不能直接去跟紡織所要資料** —— 一定會被拒絕。

正確做法是中間加一台我們自己的伺服器代轉：

```
使用者瀏覽器  →  我們的伺服器（固定 IP，持有帳號）  →  紡織所 API
```

所以現在缺三樣東西，都要問客戶：

1. **我們的中轉伺服器網址** —— 這台還沒建，要先決定誰做、放哪
2. **紡織所的帳號（token）** —— 要跟紡織所申請，需提供固定 IP、姓名、Email
3. **AI 生圖 API 的正式網址** —— 客戶文件上只寫 `127.0.0.1`，那是「他們自己電腦」的意思，我們連不到

另外有一題要先跟紡織所講清楚：他們規定「一組帳號只給一個人、綁一個 IP」。但走中轉伺服器等於全公司共用同一組帳號和同一個 IP，要確認這樣不會被判定成異常使用。

**在這之前不會停工**：程式我已經寫成「有網址就連真的、沒網址就用假資料」，開發測試照常進行，等客戶給了位址，填一行設定就切過去。
