### 2. 中轉服務不能拿掉，但不需要額外主機 🔴

Thierry 回覆「建好後來提供，屆時應該不用中轉伺服器，這機制可以拿掉」。

這裡需要澄清一個技術前提：**網站放在 GCP，不代表 API 請求來自 GCP 的 IP。**

前端 JavaScript 是在**使用者自己的電腦**上執行的。網頁檔案雖然從 GCP 下載，但瀏覽器發出的 API 請求，來源 IP 是使用者當下所在網路（家裡、公司、手機網路）的 IP，不是 GCP 那台機器的 IP。

```
❌  使用者瀏覽器 ──── 來源 IP = 使用者家裡 ────→ 紡織所 API      被拒絕
✅  使用者瀏覽器 → GCP 後端服務 ── 來源 IP = GCP 固定 IP ──→ 紡織所 API   通過
```

除了 IP，還有兩個理由讓這支後端服務非做不可：

| 理由 | 說明 |
|---|---|
| **token 外洩** | token 若寫在前端，任何使用者按 F12 開啟開發者工具就能看到，等同帳號公開 |
| **https 混合內容** | 紡織所 API 皆為 http 明碼（`http://210.71.142.39:4458/`）。網站若走 https，瀏覽器會直接封鎖對 http 的請求。經後端轉發則無此問題 |

**結論**：Thierry 說的「不用額外一台中轉伺服器」是對的 —— 那支轉發服務跑在**同一台 GCP 主機**上即可，不必另外開機器。但**轉發這個機制本身不能拿掉**。

**請確認**

- 開發階段提供的 `139.180.201.151` 是哪一台的 IP？是唯物辦公室的對外出口 IP，還是某台特定伺服器？
  （若是辦公室出口 IP，開發者在辦公室內即可測試；若是伺服器，則須從該台發出請求）

### 3. 內建圖案需要「實際公分尺寸」（新增項目）⚠️

第 10 題提到內建圖案缺分類。除了分類，還需要**每張圖案的實際公分尺寸**。

原因：貼圖在 3D 模型上的重複次數必須由實際尺寸決定 ——

```
重複次數 = 模型公分尺寸 ÷ 圖案實際公分尺寸
```

同一張圖，設計上是 5 公分的小碎花還是 30 公分的大圖騰，貼到衣服上應該差 6 倍。目前 15 張圖案都沒有尺寸資訊，唯物端暫用 9.144 cm 頂著（此數值非貴所提供，是從前一版程式反推的）。

**布樣貼圖沒有這個問題** —— `.u3m` 檔裡有明確記錄，例如：

```
3-0000001_BASE.jpg   1035 × 1053 px @ 663 dpi  →  39.65 × 40.34 mm
```

也就是這塊布的織紋一個循環約 4 公分，唯物端已依此計算。

**請提供**：15 張內建圖案各自的實際公分尺寸（或統一的預設值）。
